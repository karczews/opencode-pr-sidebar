# Proposal

## Why

Clicking the PR title in the sidebar card already opens the pull request in the browser, but nothing on screen says the title is a link. It only gets the link color, which many themes make hard to tell apart from other text. Underlining the title uses the usual cue for a link, so people can find the click target without having to know about it first.

## What Changes

- Render the pull request title in the sidebar card underlined, so it reads as a link.
- Keep the title's existing link color, terminal hyperlink, and click-to-open behavior.
- Leave the `#<number>` prefix bold and not underlined. The request names the title, and the number is a label. Assumption: if the user wants the whole `#N title` underlined, they can change this at review.
- Add a headless render test asserting that the title is underlined and that other card text (for example, the branch line) is not.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `pr-sidebar`: the "Clickable pull request link with open and copy actions" requirement gains a scenario requiring the title link to be shown underlined.

## Impact

- `tui.tsx`: wrap the title inside the existing `<a>` in `PrCard` with an underline text modifier (`<u>`), which `@opentui/solid` provides as a text node.
- `test/test-render.test.mjs`: new assertion on the captured span `attributes` (UNDERLINE bit).
- `dist/tui.js`: regenerated by `npm run compile`, because `verify:dist` requires the checked-in build to match.
- No new dependencies, no model changes, no API changes.
- Risk: the `<u>` element was verified on `@opentui/solid` 0.8.4 only. How older versions in the `>=0.6.6` peer range handle it is unverified.
- Out of scope: re-recording `docs/assets/card.gif`, which will still show the title without an underline.
